## Project overview

NaviRAG is a hierarchical RAG system that replaces vector embeddings with tree-structured document navigation. It parses Markdown into H1–H6 trees, generates per-node LLM summaries/keywords bottom-up, then uses a LangGraph workflow (select_docs → select_nodes → grade_node_content) to retrieve relevant content. A LangChain agent wraps the retriever tool for conversational Q&A. The backend is FastAPI; the frontend is React + Vite + TailwindCSS.

## Commands

```bash
# Start PostgreSQL (required for backend)
docker compose -f docker/docker-compose.yml up postgres -d

# Run database migrations
cd backend && uv run alembic upgrade head

# Backend (FastAPI with hot-reload)
cd backend && uv run uvicorn app.main:app --reload --port 8000

# Build document index from Markdown files in data/input/
uv run python data/md2tree.py

# Frontend (React + Vite dev server, port 5173)
cd frontend && npm run dev

# Frontend production build
cd frontend && npm run build

# Full stack with Docker
docker compose -f docker/docker-compose.yml up -d
```

**Workspace**: This is a uv workspace. The root `pyproject.toml` declares `backend/` as the only workspace member. Run Python commands from the project root; uv resolves the `backend` package automatically.

## Architecture

### Core RAG engine (`core/`)

- **`core/workflow/graph.py`** — LangGraph `StateGraph` with 3 sequential nodes: `select_docs` (pick doc_ids from global index), `select_nodes` (pick node_ids from each doc's nav tree via LLM `.batch()`), `grade_node_content` (LLM `yes`/`no` grading per node). State is `{query, doc_ids, node_ids, final_nodes}`.
- **`core/workflow/prompts.py`** — Hardcoded `global_index` list (doc_id → summary/keywords). Generated by `md2tree.py` and manually copied in. This is the entry point for doc routing.
- **`core/tools/local_retriever.py`** — `@tool("search_local_docs")` that calls `search_workflow.invoke()` and returns `final_nodes`. This is the only tool currently active in the agent.
- **`core/agent.py`** — Creates a LangChain agent via `create_agent()` with `SummarizationMiddleware`, `ToolRetryMiddleware`, and `ModelFallbackMiddleware`. Agent is built synchronously at import time (`asyncio.run(build_agent())`).
- **`core/models/models.py`** — Model definitions: `agent_model` (deepseek-v4-flash), `back_agent_model`, `read_model` (MiniMax-M2), `grade_model` (MiniMax-M2), `summarize_model` (MiniMax-M2). All use `ChatOpenAI` with `OPENAI_API_KEY`/`OPENAI_BASE_URL` from `.env`.
- **`core/middleware/middleware.py`** — Returns `[SummarizationMiddleware, ToolRetryMiddleware, ModelFallbackMiddleware]`.
- **`data/storage.py`** — Two `EncoderBackedStore` instances backed by `LocalFileStore`: `node_content_store` (node_id → {title, path, content, summary, keywords}) and `doc_tree_store` (doc_id → {nav tree structure}).
- **`data/md2tree.py`** — Offline indexing script: Markdown parsing (regex H1–H6 with code-block filtering), stack-based tree building, bottom-up LLM metadata generation with `asyncio.Semaphore(15)` for concurrency, produces `global_index.json` + per-doc JSON files.

### Backend (`backend/`)

- **FastAPI app** at `backend/app/main.py` with CORS, lifespan DB init/close, routers for health/documents/chat under `/api/v1`.
- **`backend/app/api/v1/chat.py`** — SSE streaming endpoint (`POST /chat/completions`). Runs `search_workflow.astream()` for retrieval, then streams LLM tokens via `agent.astream_events()`. Also CRUD for sessions/messages.
- **`backend/app/api/v1/documents.py`** — Upload Markdown files → background indexing, list/get/delete/reindex. Indexing calls `backend/app/indexing/pipeline.py`.
- **`backend/app/db/`** — SQLAlchemy async with PostgreSQL. Models: `Document` (id, name, raw_content, summary, keywords, tree_structure, status), `Node` (id, doc_id, title, path, content, summary, keywords, level), `SourceReference` (message_id → node_id → doc_id for attribution), `ChatSession`, `ChatMessage`. Session management via `async_sessionmaker`. Schema changes are managed through Alembic migrations (`backend/migrations/`).
- **`backend/app/core/`** — Mirrors root `core/` structure but with lazy agent loading (`get_agent()` async factory) and PostgreSQL-backed storage instead of LocalFileStore. The backend has its own copies of workflow, models, tools, middleware files.
- **`backend/app/config.py`** — Pydantic Settings: `DATABASE_URL`, `LLM_API_KEY`, `CORS_ORIGINS`, etc.

### Frontend (`frontend/`)

- React 19 + TypeScript + Vite + TailwindCSS 3. Two views: Chat (SSE streaming) and Document management (upload/list/delete).
- `src/components/Sidebar.tsx` — Session list + view toggle.
- `src/components/ChatPanel.tsx` — SSE consumption via `useChat` hook.
- `src/components/DocumentList.tsx` + `DocumentUpload.tsx` — Document CRUD.
- `src/api/client.ts` — Thin fetch wrapper with `/api/v1` base.

### Data flow

1. **Upload**: Markdown file → `POST /api/v1/documents/upload` → raw content stored in `documents.raw_content` → background indexing triggered.
2. **Indexing**: Content → `md_parser.py` (H1–H6 tree) → LLM metadata per node → `document` + `node` records written to PostgreSQL.
3. **Retrieval**: Query → `select_docs` reads `documents` table → `select_nodes` reads each doc's `tree_structure` → `grade_node_content` reads full node content. All use structured LLM output.
4. **Chat**: Agent receives query → may call `search_local_docs` tool → tool invokes workflow → agent synthesizes answer from `final_nodes`.

### Database migrations (Alembic)

```bash
# Generate a migration after modifying models
cd backend && uv run alembic revision --autogenerate -m "描述"

# Apply all pending migrations
uv run alembic upgrade head

# Roll back one migration
uv run alembic downgrade -1

# Show current migration status
uv run alembic current
```

- `backend/alembic.ini` — Config file; database URL is read from `app.config.settings` at runtime
- `backend/migrations/env.py` — Async migration environment using `create_async_engine` + `run_sync`
- `backend/migrations/versions/` — Migration scripts

Always run `alembic upgrade head` after pulling changes that include new migrations. The app's `init_db()` calls `Base.metadata.create_all` as a safety net for fresh deployments, but schema changes rely on Alembic.

## Environment

Copy `.env.example` (if exists) or create `.env` with:
```
OPENAI_API_KEY=<your-api-key>
OPENAI_BASE_URL=<your-api-base-url>
DATABASE_URL=postgresql+asyncpg://navirag:navirag@localhost:5432/navirag
```

The LLM provider is accessed via OpenAI-compatible API (`OPENAI_API_KEY` / `OPENAI_BASE_URL`). Models used: `deepseek-v4-flash` (agent), `MiniMaxAI/MiniMax-M2` (reader/grader/summarizer).
